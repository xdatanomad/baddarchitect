## Post copy

"Review the output" is advice. It is not a verification method.

An AI-prepared result looks finished long before it is ready to use. A customer brief repeats last month's commitment. A cost analysis reports a drop but misses a change in transaction volume. A policy summary gives the general rule and skips the exception that applies to this person.

Each one is fluent. Each one is plausible. You can read it twice and still miss the problem.

Engineering already solved this. We don't accept a code change because the diff looks clean. We define expected behavior, reproduce the issue, run the tests, inspect the change, and set a review gate that matches the risk.

Internal AI use needs the same habit, applied proportionally. A rough brainstorm needs a glance. A customer escalation, a financial call, a policy read, or a code change needs real evidence and a clear place to stop.

Before you rely on an AI-prepared result, answer three questions:

1. What could be wrong even if this looks convincing?
2. What evidence, calculation, or test would reveal that?
3. What uncertainty would make me stop instead of keep editing?

That turns review from a vague responsibility into part of the work.

Decision rule: don't use an AI result for a consequential decision if you can't name what to check, the authoritative source or test, and the condition that makes you stop or escalate.
